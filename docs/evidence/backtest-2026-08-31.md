# The model, scored against 1,276 windows that have since resolved

**2026-08-31, Shannon (50312). `node scripts/backtest.ts --limit 800`; the raw run is
[`backtest-2026-08-31.txt`](backtest-2026-08-31.txt).**

`fair-value-2026-08-31.md` closed with "**No backtest.** The model has never priced a
window that has since resolved." It has now priced 1,276 of them, and the answer is not
the one this project was hoping for.

The morning's live logs had raised a sharper question. The book disagreed with the model
**in one direction**: above it on every window that had risen, below it on the one that
had fallen. Either the book extrapolates a move it should not, or the model misses
something a backward-looking vol estimate cannot see. A snapshot cannot separate those.
A resolved window can, and the venue has finalised thousands.

## Method

For each finalised binary window with at least one trade, replay what the model **would**
have said at the instant of that market's last trade, and score it against the outcome
next to the book's own price at the same instant.

Every fetch is windowed with `to`, which is the whole point — a candle or a tick from
after the scored instant is lookahead, and lookahead makes any model look excellent. The
strike is reconstructed exactly the way the live path reconstructs it, from the feed's
first tick at or after `tradingStart`, so an error there shows up in the score rather than
being assumed away.

The score is **Brier**, mean `(p − outcome)²`. It is proper: minimised only by reporting
your true belief, so a forecaster cannot improve it by hedging toward 0.5. Always-0.5
scores 0.25 and is the line both sides must beat to be worth anything at all.

Which side of `payoutNumerators` is "up" is inferred and then checked, not assumed: the
book averaged **0.662** on windows where index 0 paid and **0.337** where it did not. If
that had come out the other way every number below would be inverted, so the script
refuses to print rather than trusting it.

The script would have called that gap a win. It now requires a margin of 0.005 before
naming a winner, because the σ scan below moves Brier by less than that across a threefold
range of the model's single most important input — a gap smaller than the model's own
parameter noise is not a result.

This is the answer to the morning's question, and it is the opposite of the flattering one.
**At both extremes the book wins, and not narrowly.** Where the book sits 0.10 or more
above the model, the window pays 75% of the time: the book said 0.709 and the model said
0.572. Where the book sits 0.10 or more below, it pays 36%: the book said 0.296 and the
model said 0.473.

The model is dragged toward the middle exactly where the book is confident. The book is
not extrapolating a move it should not — it is reading something the model does not have.

## It is not σ, and that was worth testing

Being pulled toward 0.5 is the signature of an over-large σ: a bigger σ shrinks d₂ and
drags every probability to the middle. That is a one-parameter hypothesis, the rows carry
every input, so it costs no fetches — rescale σ and re-price the same windows. Fitted on
the older half, scored on the newer half, because a scale chosen and graded on the same
data is a curve fit wearing a finding's clothes.

| σ × | Brier, train (n=638) | Brier, test (n=638) |
|---|---|---|
| 0.5 | 0.1554 | 0.2004 |
| 0.7 | 0.1495 | 0.1933 |
| 0.9 | **0.1484** ← best on train | 0.1910 |
| 1.0 | 0.1489 | **0.1908** |
| 1.2 | 0.1510 | 0.1917 |
| 1.5 | 0.1557 | 0.1944 |

The optimum on the training half is 0.9× and on the test half it is 1.0×, and the whole
curve from 0.8× to 1.2× spans 0.001 of Brier. **σ is not biased.** The hypothesis was
specific, it was testable, and it is rejected — so the tail failure is about *direction*,
not volatility, and no amount of tuning the vol estimator will reach it.

It is **calibrated**. When it says 0.253, 26.2% pay. When it says 0.958, 97.7% pay. Across
ten bands it never strays far from the diagonal, which is exactly what a probability is
supposed to do and is not something the project could claim before today.

## What this changes, and what it does not

- **`FV_MAX_EDGE = 0.1` stays, and its justification changes.** It was introduced as
  "one of us is wrong and the spread will not pay for finding out which." The answer is
  now known: in that band it is *us*. The rule is still right — refusing to quote where
  your own model is unreliable is sound risk control — but it protects the vault from
  Abadi's model, not from a stale incumbent. The comment and the log line say so now.
- **The three-tick skew toward fair stays.** It only applies where the bot quotes, and in
  the 0.05–0.10 band the model is measurably closer than the book (off by 0.010 against
  0.079 on 163 windows). That is the one band where leaning toward the model is supported.
- **Nothing here fixes the strategy.** The ledger's adverse rate is 18% against the ~9% the
  spread needs. A forecast that ties the book cannot close that gap, and this file is the
  evidence that the model was never going to. What it can do is stop the bot quoting into
  windows it cannot price, which is a smaller claim and a true one.
- **The 86400s row is 32 windows.** The model's 0.1695 against the book's 0.1890 there is
  the only tier where either side leads by a real margin, and it is far too small a sample
  to act on. The bot does not quote that tier anyway.

## Limits

- One observation per window, at its **last trade**, median 645s before expiry. A window
  with two trades contributes the later one. This measures the book at the moment it was
  most recently willing to transact, which is the fairest single instant available from the
  indexer, but it is not the instant Abadi would have quoted at.
- `lastPrice` is a traded price, not a mid. A trade crosses a spread, so the book's number
  carries up to half a spread of noise that the model's does not — which, if anything,
  flatters the model.
- Testnet. The flow is thin, the oracle is a testnet oracle, and 900s windows are 63% of
  the sample.
